你这个判断是对的：**目前这版项目和“内存池”确实关联不强**。

现在代码虽然实现了：

```plain
摄像头采集线程 -> 队列 -> 网络发送线程 -> TCP 分片发送
```

但每一帧仍然在频繁做这些事情：

```cpp
RawFrame(id, frame);        // 内部 image = mat.clone()
std::vector<uint8_t> header // 每帧/每分片动态申请
std::vector<uint8_t> payloadBuffer // 服务端接收时动态申请
```

所以它只是“生产者-消费者 + 原始字节流 + 分片传输”，还不能很好体现你简历里说的：

```plain
使用内存池大幅降低频繁动态内存分配带来的系统开销与内存碎片化
```

如果你想让项目和“内存池”真正挂钩，应该把内存池放在**图像帧缓冲区管理**这一层。

# 一、为什么现在没有体现内存池？
现在你的 `RawFrame` 大概是这样：

```cpp
RawFrame(uint64_t id, const cv::Mat& mat)
    : frameId(id),
      timestamp(std::chrono::steady_clock::now()) {
    image = mat.clone();
}
```

这里每采集一帧都会 `clone()`，本质上就是：

```plain
申请一块 921600 bytes 的堆内存
拷贝图像数据
封装成 RawFrame
放入队列
```

如果是 640x480x3，10 FPS：

```plain
每秒申请/释放约 9 MB 图像内存
```

如果是 1920x1080x3，30 FPS：

```plain
每帧约 6 MB
每秒约 180 MB 图像内存申请/释放
```

这时候频繁 `new/delete` 或 OpenCV 内部内存分配就会产生明显开销，也容易造成内存碎片。

所以内存池应该解决的是：

```plain
不要每一帧都重新申请一块图像内存；
提前准备 N 块固定大小的 frame buffer；
采集线程从池里取 buffer；
发送线程发送完后归还 buffer。
```

---

# 二、推荐架构：把 RawFrame 从“拥有 cv::Mat”改成“持有内存池 buffer”
现在是：

```plain
CameraCapture
    cap.read(frame)
    RawFrame(id, frame) 里面 clone 一份
    queue.push(RawFrame)

RawFrameSender
    从 RawFrame.image 里取 data 发送
```

改成：

```plain
FrameBufferPool
    预分配 N 块固定大小 buffer

CameraCapture
    从内存池 acquire 一个 buffer
    cap.read(tempFrame)
    memcpy 到 buffer
    queue.push(RawFrame)

RawFrameSender
    发送 RawFrame 里的 buffer
    发送完成后自动释放/归还内存池
```

核心变化是：

```plain
RawFrame 不再频繁分配大块内存；
RawFrame 只引用内存池中的一块 buffer；
buffer 生命周期由 shared_ptr + 自定义 deleter 管理；
发送线程用完自动归还。
```

# 三、可以加入一个 `FrameBufferPool`
新增文件：

```plain
FrameBufferPool.h
FrameBufferPool.cpp
```

## `FrameBufferPool.h`
```cpp
#ifndef FRAME_BUFFER_POOL_H
#define FRAME_BUFFER_POOL_H

#include <vector>
#include <queue>
#include <memory>
#include <mutex>
#include <condition_variable>
#include <cstdint>
#include <cstddef>

class FrameBufferPool {
public:
    using BufferPtr = std::shared_ptr<uint8_t[]>;

    FrameBufferPool(size_t bufferSize, size_t bufferCount);

    BufferPtr acquire();

    size_t bufferSize() const;
    size_t totalCount() const;
    size_t availableCount() const;

private:
    void release(uint8_t* buffer);

private:
    size_t bufferSize_;
    size_t bufferCount_;

    std::vector<std::unique_ptr<uint8_t[]>> storage_;
    std::queue<uint8_t*> freeBuffers_;

    mutable std::mutex mutex_;
    std::condition_variable condition_;
};

#endif
```

## `FrameBufferPool.cpp`
```cpp
#include "FrameBufferPool.h"

FrameBufferPool::FrameBufferPool(size_t bufferSize, size_t bufferCount)
    : bufferSize_(bufferSize),
      bufferCount_(bufferCount) {
    storage_.reserve(bufferCount_);

    for (size_t i = 0; i < bufferCount_; ++i) {
        std::unique_ptr<uint8_t[]> buffer(new uint8_t[bufferSize_]);
        freeBuffers_.push(buffer.get());
        storage_.push_back(std::move(buffer));
    }
}

FrameBufferPool::BufferPtr FrameBufferPool::acquire() {
    std::unique_lock<std::mutex> lock(mutex_);

    condition_.wait(lock, [this]() {
        return !freeBuffers_.empty();
    });

    uint8_t* raw = freeBuffers_.front();
    freeBuffers_.pop();

    return BufferPtr(raw, [this](uint8_t* ptr) {
        this->release(ptr);
    });
}

void FrameBufferPool::release(uint8_t* buffer) {
    {
        std::lock_guard<std::mutex> lock(mutex_);
        freeBuffers_.push(buffer);
    }

    condition_.notify_one();
}

size_t FrameBufferPool::bufferSize() const {
    return bufferSize_;
}

size_t FrameBufferPool::totalCount() const {
    return bufferCount_;
}

size_t FrameBufferPool::availableCount() const {
    std::lock_guard<std::mutex> lock(mutex_);
    return freeBuffers_.size();
}
```

这个类的作用是：

```plain
初始化时一次性分配 N 块图像缓冲区；
采集线程 acquire；
发送线程用完后 shared_ptr 自动归还；
整个运行过程中大块图像内存不再反复申请释放。
```

# 四、改造 `RawFrame`
现在的 `RawFrame` 不再保存 `cv::Mat image`，而是保存原始 buffer。

## 新版 `RawFrame.h`
```cpp
#ifndef RAW_FRAME_H
#define RAW_FRAME_H

#include <cstdint>
#include <cstddef>
#include <memory>
#include <chrono>

struct RawFrame {
    uint64_t frameId;

    uint32_t rows;
    uint32_t cols;
    uint32_t type;
    uint32_t elemSize;

    uint64_t totalBytes;

    std::shared_ptr<uint8_t[]> buffer;

    std::chrono::steady_clock::time_point timestamp;

    RawFrame()
        : frameId(0),
          rows(0),
          cols(0),
          type(0),
          elemSize(0),
          totalBytes(0),
          timestamp(std::chrono::steady_clock::now()) {}

    RawFrame(
        uint64_t id,
        uint32_t r,
        uint32_t c,
        uint32_t t,
        uint32_t e,
        uint64_t bytes,
        std::shared_ptr<uint8_t[]> data
    )
        : frameId(id),
          rows(r),
          cols(c),
          type(t),
          elemSize(e),
          totalBytes(bytes),
          buffer(std::move(data)),
          timestamp(std::chrono::steady_clock::now()) {}

    bool empty() const {
        return !buffer || totalBytes == 0;
    }

    const uint8_t* data() const {
        return buffer.get();
    }
};

#endif
```

这样 `RawFrame` 就变成了一个轻量级元数据对象。

## `CameraCapture.cpp` 关键修改
构造函数：

```cpp
CameraCapture::CameraCapture(
    int cameraIndex,
    BlockingQueue<RawFrame>& outputQueue,
    FrameBufferPool& bufferPool
)
    : cameraIndex_(cameraIndex),
      width_(640),
      height_(480),
      fps_(10),
      outputQueue_(outputQueue),
      bufferPool_(bufferPool),
      running_(false),
      frameId_(0) {}
```

采集循环里，原来是：

```cpp
RawFrame rawFrame(id, frame);
outputQueue_.push(rawFrame);
```

改成：

```cpp
if (!frame.isContinuous()) {
    frame = frame.clone();
}

uint64_t bytes = static_cast<uint64_t>(frame.total() * frame.elemSize());

if (bytes > bufferPool_.bufferSize()) {
    std::cerr << "[CameraCapture] 当前帧大小超过内存池 buffer 大小, bytes="
              << bytes
              << ", poolBufferSize="
              << bufferPool_.bufferSize()
              << std::endl;
    continue;
}

auto buffer = bufferPool_.acquire();

std::memcpy(buffer.get(), frame.data, static_cast<size_t>(bytes));

uint64_t id = ++frameId_;

RawFrame rawFrame(
    id,
    static_cast<uint32_t>(frame.rows),
    static_cast<uint32_t>(frame.cols),
    static_cast<uint32_t>(frame.type()),
    static_cast<uint32_t>(frame.elemSize()),
    bytes,
    buffer
);

outputQueue_.push(rawFrame);
```

记得加头文件：

```cpp
#include <cstring>
```

这个地方就真正体现了内存池：

```plain
frame buffer 来自 FrameBufferPool
不再 RawFrame 里面 clone 出一块新内存
发送完自动归还内存池
```

# 八、但还要注意一个问题：OpenCV 采集本身仍然会分配
即使你用了内存池，这句：

```cpp
cap.read(frame);
```

OpenCV 内部仍然可能管理自己的缓冲区。

所以我们这个内存池主要优化的是：

```plain
你的业务层 RawFrame 队列里的图像副本
```

它不能完全消除：

```plain
摄像头驱动层 / OpenCV VideoCapture 内部的缓冲
```

但它已经足够支撑你简历里说的：

```plain
针对高频碎片化数据流，采用生产者-消费者模型实现图像采集与网络传输解耦；
使用内存池降低频繁动态内存分配开销与内存碎片化。
```

因为你的项目业务数据流中，最大、最频繁的对象就是图像帧 buffer。

# 九、服务端也可以加内存池
服务端现在如果是这样：

```cpp
std::vector<uint8_t> rawBuffer(frameHeader.totalBytes);
```

那它每接收一帧也会动态分配。

可以类似改成：

```plain
FrameBufferPool receivePool
```

然后：

```cpp
auto buffer = receivePool.acquire();
recvAll(clientSocket, buffer.get() + chunkHeader.offset, chunkHeader.payloadSize);
```

这样服务端也能避免每帧申请 `rawBuffer`。

不过建议你先改客户端，因为你简历里强调的是：

```plain
图像采集与网络传输链路
```

客户端更重要。

# 十、你可以在项目描述里这样说
等你加了内存池之后，项目描述可以写得更真实：

```plain
针对高频原始图像流在采集、排队与网络发送过程中频繁创建大块缓冲区的问题，设计固定块帧缓冲内存池，预分配多块连续图像缓冲区，并结合 shared_ptr 自定义释放器实现缓冲区自动归还，减少 cv::Mat clone 与 std::vector 动态扩容带来的堆分配开销，降低长时间运行下的内存碎片化风险。
```

如果想更工程化一点：

```plain
将图像帧数据从 cv::Mat 生命周期中解耦，使用 RawFrame 仅保存帧元数据和池化 buffer 引用；采集线程从内存池获取空闲缓冲区并写入原始字节，发送线程完成 TCP 分片传输后自动释放引用并归还缓冲区，实现采集、缓存、发送三个模块之间的低耦合数据流转。
```

# 十一、总结一句
你现在这版确实只是：

```plain
生产者-消费者 + TCP 原始字节流 + 应用层分片
```

要体现“内存池”，应该把它加在：

```plain
RawFrame 的图像数据存储层
```

也就是让：

```plain
每帧图像数据不再通过 cv::Mat clone / vector 临时申请
而是从 FrameBufferPool 里取固定大小 buffer
发送完成后自动归还
```

这样整个项目的技术链路就完整了：

```plain
摄像头采集
    ↓
内存池帧缓冲
    ↓
生产者-消费者队列
    ↓
TCP 应用层分片协议
    ↓
服务端重组原始字节流
```
